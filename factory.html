Step 1: send the requirement email

Keep the subject fixed. Put one field per line; keep the labels unchanged. Attachments may be PDF, DOCX, XLSX, images or ZIP.

Do not send passwords, private keys, full ID numbers or customer-sensitive data. Mask demo data before sending.

Step 2: confirm the scope

Operations will reply with the scope, roles, data model, page list, acceptance criteria and delivery window. Reply “confirmed” to let the factory start. If fields are missing, reply in the same thread with the missing values.

Step 3: approve the prototype (mandatory gate)

The prototype uses the same native Boot template, components, home dashboard, menus and visual language as the final app. It is not a separate static mock.

  • Pages and navigation
  • Home dashboard metrics and shortcuts
  • List columns and filter fields
  • Form fields and validation
  • Role-specific menus
  • Mobile layout
Important: production does not start without prototype approval. Layout/data/API changes after approval go through the change process.

Step 4: trial and acceptance

After deployment you receive one account per role:

  • Admin account: full configuration and all menus.
  • User account: only the menus for the delivered business function. It must not see system settings or internal tools.

Do not use the admin account to prove the normal user path. Check the home dashboard, role menus, CRUD/business flow, permissions, empty states, errors and mobile layout.

If something fails, reply with the page, steps, expected result and screenshots. The factory repairs and returns a new version.

Step 5: customer confirmation and changes

After operations acceptance, you receive the trial URL, accounts and scope. You can confirm delivery or request a change. Changes are versioned; the old version is never overwritten.

Timing, scope and limits

  • Automatic reply: immediate. Requirement review: within one business day.
  • Prototype: usually 1–2 business days after scope confirmation; production, QA and deployment depend on scope and queue.
  • Free starter scope: one core module, smallest runnable instance, public case by default; extra modules, private cases, complex integrations, migration and commercial licenses are quoted separately.
  • We do not accept illegal, classified or high-risk projects; acceptance is subject to operations review.
  • Testing is internal/controlled by default; public launch requires both sides to confirm.

FAQ

Can I send only an attachment?

Send the body and attachment together. The body creates the ticket; attachments provide detail. Missing fields put the ticket into “needs info”.

I lost the ticket number.

Reply in the original email thread from the same address, or contact operations. Do not open a duplicate ticket.

Why can’t the user account see settings?

Role isolation. The user account only gets the delivered business menus; the admin account gets full configuration.

Can I change the prototype after approval?

Yes, through the change process. Prototype approval is a production gate; scope, data or API changes are re-estimated.
