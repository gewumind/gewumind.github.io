Step 1: send the requirement email

Keep the subject fixed. Put one field per line; write “none” if not applicable. Attachments may be PDF, Word, Excel, images or ZIP.

Do not send passwords, private keys, full ID numbers or customer-sensitive data. Mask demo data before sending.

Step 2: confirm the scope

We send back a one-page scope: what is included and excluded, who uses it, which data and pages are needed, how acceptance works, and the expected delivery window. Reply “confirmed” to start the prototype. If something is wrong, reply in the same thread.

Step 3: review the prototype before build

The prototype should match the final system: same page structure, home page, menus and visual style. It is not a separate static mock with a different look.

  • Are all pages present and is navigation natural for your team?
  • Does the home page show the numbers and shortcuts you need?
  • Are list columns, form fields, required fields and messages sufficient?
  • Which menus do the admin and user accounts see?
  • Does it work on a phone?
Please approve before build. After approval, changes to page structure, data tables or APIs go through a change request and may change the delivery date.

Step 4: trial with two accounts

  • Admin account: all menus, settings and permissions. For you to manage the system.
  • User account: only the business menus delivered for this project. For daily users.

Use one account per role. Do not give the admin account to normal users.

During trial, check the home page, the user account’s menus, your core business flow, permissions, empty states, error messages and mobile layout. If something fails, reply with the page, steps, expected result, actual result and screenshots.

Step 5: confirm delivery or request changes

If the trial meets your expectations, reply to confirm delivery. If you need changes, describe what to add, change or remove. We assess impact and timing first, then build a new version. Previous approved versions are retained.

FAQ

Can I send only an attachment?

Send the email body and attachment together. The body creates the ticket and attachments provide detail. Missing fields may put the ticket into “needs info”.

I lost my ticket number.

Reply in the original thread from the same email address. Do not create a new ticket; it will queue again.

Why can’t the user account see settings?

Role isolation. The user account only gets the delivered business menus; the admin account gets full configuration.

Can I change the prototype after approval?

Yes, through the change process. Prototype approval is the build gate; later page, data or API changes are re-estimated.

Why is the ETA a range?

Requirements differ and other orders may be ahead. The email gives an estimate, not a guaranteed time.
